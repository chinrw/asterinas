# Environment Variables

The OSDK tool uses the following environment variables to customize compilation and target behavior. 

## OSDK-Specific Variables
- `OSDK_TARGET_ARCH`: If set, OSDK will use the specified value as its default target architecture (e.g., x86_64, riscv64). 
If not set, OSDK will default to the host architecture.

## Variables Referenced from `OSDK.toml`

The `qemu.args` value in `OSDK.toml` is expanded through the host shell before
it is passed to QEMU, so it can reference environment variables using the
usual `${VAR}` or `${VAR:-default}` syntax. The scaffold generated by
`cargo osdk new` uses this to locate the OVMF UEFI firmware:

- `OVMF_DIR`: The directory containing the `OVMF.fd` (firmware code) and
  `OVMF_VARS.fd` (firmware variable store) files used to boot the kernel
  under QEMU. If not set, it defaults to `/root/ovmf/release`, which matches
  the firmware layout of the OSDK Docker image.

  If the `OVMF_VARS.fd` file resolved through `OVMF_DIR` is not writable
  (for example, when `OVMF_DIR` points into the read-only Nix store), OSDK
  copies it into the bundle's directory under `target/osdk/` and points
  QEMU at that writable copy instead. The original file is never modified.
